# Stage2a：跨城市五类用途模型的下一轮计划

2026-10-26。状态：数据盘点与文献核查完成；本文件是待执行方案，不是新模型结果。目标是给定单栋 footprint 后的实际用途估计，另报 primary/auxiliary 和可校准的拒答。检测性能另行测量。

## 优先决策

优先试 **可靠的多城市监督 + 目标/上下文分开的视觉特征 + 小分类头**，保留 ConvNeXt 基线，增加 DINOv3 视觉编码器对照。Qwen3-VL 的有监督适配是有价值的竞争路线；先做 SFT/QLoRA，暂不投入 GRPO、长推理链生成、全量 8B 微调或从头预训练。

依据和原论文见 [文献笔记](../../../../literature-review/STAGE2A_GENERALIZATION_20261026.md)。这个顺序依据当前失败模式和实验成本，尚未证明哪条路线性能最好。

已下载的 NYC 1000 候选中含 Education 27、Religion 33、Warehouse 17、Factory 31、Garages 17 等来源类别；这是可审核的候选量，尚不是可直接使用的五类或角色真值。先复用这些文件，不重新批量下载同一数据。扩大 NYC 样本时优先增加少数类别、形态和地区覆盖，不能把再增加住宅数量视为泛化机制。

Harris/LA/SD 都已有结果反馈。旧 SD 可作为后续开发数据，但不能再作为新方案完全未接触的最终测试。当前没有独立核实、覆盖五类及附属结构的多城市测试集。

## 先做数据，保证比较回答同一个问题

1. 固定语义：small=单栋 1–3 户，multi=单栋至少 4 户；商业、institutional、other 沿用本轮定义。停车/仓储等支持用途与 primary/auxiliary 分开。`other` 是已知用途，`unknown` 是未能可靠判定，不把缺失标签当第六类真值。
2. 每条监督保留 footprint/physical ID、地块 ID、城市、空间块、影像日期/原生 GSD、来源用途、核实用途、角色、证据来源与日期、可判定性。允许只有用途或只有角色标签；缺少哪一项就不计算该项监督损失，不自动填 primary。
3. 先建约 600–1000 栋的核实开发集，覆盖至少 3 个城市/地区；这是预算起点，不是统计充分性保证。优先 multi、住宅外形的商业、宗教/学校/医院、工厂/仓库、主楼/车棚。第一批复用 Harris/NYC/SD 可核实候选；必要时扩充新的开发城市。附属结构至少来自多个地块和区域，不能反复复制几个车棚。
4. 同地块/相邻重叠影像/同一物理楼栋放在同一空间组；先划组再裁剪与增广。按最宽输入视野检查不同 split 的图像覆盖重叠，避免 300m 上下文泄漏。测试区域也不参与自监督适配或伪标签训练；若使用，另称域适配实验。
5. 最终测试另选至少 2 个此前未用来选模型的城市，按用途和空间块抽样，初始目标每城约 250 栋、每类约 50 栋，并单列角色样本。实际数量由证据可得性和区间宽度决定；不能为凑齐配额把弱标签升为 Gold。最终标签应由独立核实流程形成，单纯本助手的视觉判断或许可记录命中不够。
6. 测试包括一个类别分层诊断集和一个独立的自然分布样本。前者回答少数类能否识别，后者估计实际误报/审核负担；分层集的 overall accuracy 不能外推城市总体。单位数和用途代码作为监督证据，不泄露进影像模型输入。

## 最小模型与受控比较

所有新训练比较使用同一批可评分建筑、标签版本、两种视野、几何信息和空间 split。模型允许有各自必要的图像归一化，记录原始 GSD、物理窗口和最终像素尺寸。精细近景保留目标细节，宽图提供邻域；不能只把目标缩小到一幅大图里。CNN 早先 ring20m 的失败与 VLM 双视野的收益都保留为证据，不预先认定双视野对所有编码器有效。

| 阶段 | 对照 | 要回答的问题 |
|---|---|---|
| 0 | 既有 N1、旧集成、Qwen 零样本 | 在新核实开发集上建立同样本起点；三类模型只作共享三类比较 |
| 1a | 同一 ConvNeXt-Tiny，旧来源训练 vs 加入核实多城样本；先比较共享三类 | 单纯改善监督能带来多少变化？输入、预算和选择规则固定 |
| 1b | ConvNeXt 五类：近景 vs 近景+上下文 | 五类和双视野的新强监督基线；不与旧三类 full-five 分数直接作能力比较 |
| 2 | DINOv3 ViT-B/16 Web，冻结编码器并训练小头 | 新表征是否在相同监督上提升？86M 版本先提供低成本对照 |
| 3 | Qwen3-VL-8B 零样本 vs 同模型 QLoRA SFT | 任务适配能否修复 multi、institutional 和角色失败？ |
| 4 | 仅对阶段 1–3 的领先方案做有限解冻；若 DINO 有收益，再比较 ViT-L Web/SAT-493M | 冻结特征是否已经足够？同规模 Web/Sat 对照避免预设遥感权重必胜；收益能否抵偿成本？ |

阶段 1/2 保持结构简单：RGB 编码器，近景目标 mask 的 area-weighted pooling，宽图池化，已有四个几何量拼接；用途头和二分类角色头分别训练。DINO 的 mask 用于 token pooling，先保持预训练 RGB 输入不变。另保留近景-only消融；这是目标与上下文的分开表示，不实现额外图网络或复杂跨注意力。冻结特征只计算一次并按输入/模型哈希缓存，再训练分类头。

N1 的自然采样/plain CE 是起点。先让数据覆盖更合理，再在开发集最多比较一种城市均衡采样；不同时引入重采样、类别权重、focal 等多项改动。若使用城市均衡采样，报告各城市和类别的实际暴露次数。

Qwen 初始 SFT 输出短结构化用途/角色结果，用核实标签监督；不把当前 VLM 的推断理由当真值或让它自产标签再自评。优先保留 8B 以隔离适配效应；若单 A30 双图训练不能满足显存/时间预算，再明确改为 4B，并补该 4B 的零样本基线。低 rank QLoRA 和视觉 token 上限先做短硬件预检，不声称已有显存/耗时结果。仅冻结视觉塔的适配若失败，要分清语言映射与视觉表示瓶颈，不能把一次 SFT 失败等同于所有 VLM 都无效。

## 选择、拒答与成功标准

- 在开发城市轮流留一城评估，按城市平均 macro-F1 选配方，记录最差城市和每类 P/R。同一配方先跑 2 个种子筛选，领先方案完成 3 个种子；不得只报 seed42 或最佳 checkpoint 的最终测试成绩。
- 最终城市只在方案、阈值和评分脚本固定后打开。初始有意义收益门槛：相对同数据新基线，平均 macro-F1 至少 +0.05，最差城市不退步，multi/institutional 的召回不能继续接近零；各城关键类下降超过 5 个百分点必须单列并解释。这里是决策门槛，不是预期成绩或论文发表标准。
- 对最终配对差值按空间块重采样给区间；城市数量少时，逐城报告优先于笼统“普遍泛化”。若区间很宽，不把正点估计叫稳定增益。开发城市间验证也不等于新的独立城市测试。
- 用校准开发集确定拒答阈值，冻结后报告目标 80%/90% 覆盖的操作点在外城实际达到的覆盖、选择性错误率、每类保留比例，以及全部样本正确率。Unknown 在 correct/all 中不算正确；未知标签样本不混入有真值分类分母。VLM 自报 confidence/unknown 不能直接作为校准概率。
- 角色单独报 auxiliary precision/recall/F1、混淆矩阵及分城市结果，不用高比例 primary 的 overall accuracy 代替。
- 记录 GPU 时间、峰值显存、两图预处理、每栋 p50/p95 推理时间和失败率；不用参数量或论文其他硬件上的时间替代实测。

## 何时才做 RL 或增加模态

SFT 已有稳定收益、仍存在可明确核验的结构化决策错误，而且有独立用途/角色标签时，才值得增加一个小型 GRPO 对照。奖励基于核实正确性；格式正确或解释更长不代表用途正确。所有测试标签隔离于 reward 和模型选择。

若错误持续集中于屋顶外观无法区分的用途/户数，应测试额外证据的价值：另立 image+height 或 image+street-view/POI 实验，保留 image-only 比较，并测模态缺失时的性能。标签来源的同一用途字段不能又当预测输入；POI/街景也必须时间、位置一致。增加模态后的收益只支持相应输入条件下的模型。

## 代码、算力和论文边界

- 实验训练入口在 X9 的 `II_package/scripts/stage2a/`，其 `common.py` 已支持 `mask_downsample_mode=area`。仓库 handoff 内的历史 `scripts/stage2a/common.py` 仍是 nearest 实现。后续必须固定实际 import 路径和代码哈希，不能误用旧副本重现小 mask 消失问题。此次没有改动两者。
- 复用既有物理去重、数据集、推理导出和评分逻辑；五类、角色、unknown 只在独立实验输出中实现。当前生产概率和暴露头依赖三类，未经重新训练/验证不直接替换接口。
- 既有 TAMU A30 24GiB 是首选实验资源；本轮没有重测硬件、启动 GPU 作业或暂停服务。3080 的具体显存和在线状态仍需训练前核实。特征提取可缓存，分类头用 CPU/小 GPU；Qwen QLoRA 的可用配置须实测，不能用 BF16 推理峰值推断训练能放下。
- 文章可验证的主张应是：特定城市/影像条件下，建筑级监督与表征/上下文是否提高用途及角色估计，误差如何影响类型面积或暴露汇总。换 backbone 或 LoRA 本身不是已经成立的方法创新。
- 同时做 oracle/reference footprint 和 Stage1 predicted footprint 两种评估，分清分割漏检、匹配错误和用途错误。用途准确率不是 detection AP；暴露代理改善不是实测人口精度。

本轮只完成文献、盘点和实验设计；没有训练新模型，也没有声称目标 accuracy 已达到。
